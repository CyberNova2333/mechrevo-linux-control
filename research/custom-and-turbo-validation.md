# 2026-11-14：自定义入口与狂暴子模式实机验证

适用范围：MECHREVO YAOSHI Series-XxAF55xx / BIOS N.1.33MRO91 / Linux 6.8.0-149 / NVIDIA 595.99.02。未连接水冷。

## 已安装的功能

GUI 性能页新增“自定义基础档 · 白色”，可以进入并返回办公、均衡、狂暴。用户在第二轮 15 秒测试中明确确认白色→紫色；EC 两次记录均完整恢复。基础档只控制模式入口，不提供自定义功耗、超频、温度目标或风扇曲线，不代表 Windows 自定义 profile 已完整迁移。

新版官方服务的 `MyFanManager_RamFan1p5.SetFanMode` (0x060019b5) 对 Custom 使用：
1. CustomerModeLightOn → 0x727 bit 6 置位，保留同字节 PL4D 等位。
2. 0x751 写 0（FanBoost 未启用）。
3. 0x726 bit 7 置位，保留其他位。

本机回读 0x726=80、0x727=C0、0x751=00、0x7E8=20；退出后恢复原值。固件 PMSC 明确在 CUME=1 时选择模式 3，因此该标志不仅用于灯光。此次没有把完整 profile 的功耗、风扇表或超频控制冒充成已完成。

实际运行也出现了普通狂暴 0x751=10（此前按键记录为30）。OEM 写入值与固件 TBME/UFME 定义证实 10/30 都是普通狂暴，00/20 都是普通均衡；00 是否为自定义必须结合两个 custom 标志判断。助手已修正，避免把普通均衡误认成自定义，或因附加 bit5 消退而永久锁死切档。

助手仅接受固定四档名称，没有任意寄存器或数值接口。仍执行精确 DMI/BIOS/iomem 校验、进程锁、状态二次检查、按位保存、回读与有条件回退。遇到其他控制程序 APPE、功耗/TCC/风扇速率覆盖或不完整 custom 状态时拒绝操作。回退失败会明确报告，不隐瞒部分完成。

## 狂暴子模式：命令已定位，策略效果未验收

已静态恢复官方 5.56.60.46 服务中的 5,765 个受保护方法体，均通过方法格式和 VBPD 尾标记检查。这不是执行 OEM 程序，也不意味着全量代码已经审计。原始包、恢复的指令和分析镜像只保存在本机 cache；Git 和维护备份仅保存协议事实、目标方法哈希和测试记录。

对应方法：
- 0x0600198e UserSet_Cpu_Core_Offset_Extreme：0x728 bit0 清零，再 WMI 0x5000000000A。
- 0x0600198f UserSet_Cpu_Core_Offset_Silent：0x728 bit0 置一，再 WMI 0x50000000009。
- 0x06001496/1497 为上述 WMI 方法；本机 DSDT 两个命令均调用 EC0.PMSF()。
- 0x06001990 SetbitValue 参数采用从1开始的位编号，已逐条核对，因此这里确实是 bit0。

用精确机型限定的临时内核桥接模块，经 ACPI ECRW → PMSF 验证了高能→静音→高能，包含空闲及约63W GPU负载两轮。TB43 稳定回读，相关非目标字节保持。GPU最高61°C，没有掉线或 Xid。负载稳定阶段风扇原始值和 GPU 功耗没有可辨识的子模式差异，因此不声称实现43/46dB噪声目标或完整 Windows 功耗策略。

PMSF 以及普通办公/均衡/狂暴切档均触发 NVIDIA `nvAssertFailedNoLog ... osapi.c:2116`。对应版本官方源码确认它位于“不支持该 ACPI 通知”的默认分支：
https://github.com/NVIDIA/open-gpu-kernel-modules/blob/595.99.02/src/nvidia/arch/nvalloc/unix/src/osapi.c#L2116

这说明日志并非新增自定义入口独有，也不是观察到 GPU 崩溃；但 ACPI 返回成功不能证明 NVIDIA 接受了厂商功耗通知。需继续核对 Linux GPU 策略通知及 OEM 初始化/风扇上限，不能简单删除日志或跳过通知就宣称修复。

试验已恢复 TB43=0，卸载临时模块。未安装 DKMS、开机项或内核补丁。GUI 暂不提供狂暴子模式按钮，实验源代码仅放在 research/experimental-turbo，维护更新不得自动安装它。

## Logo 灯与边界

用户补充机身 Logo 可发光。0x7AB 为相关参考项目标注的共享 Logo/模式索引字节，本次仅记录、不写入；实机一直为01，测试也覆盖高位灯光位不被修改。没有验证或发布独立 Logo 灯控制功能。键盘与灯带的已验证 HID 功能不受本次性能修改影响。

## 验证与维护

14项测试：灯效回归、模式白名单、custom进入/退出、每一步接受写入后报错的回退、机身按键竞争、无操作重复请求、OEM编码别名、非目标/Logo位保持。另有实际 pkexec 和 GTK 按钮端到端验证，恢复到原来的紫色狂暴档。

GUI、助手、测试、完整研究记录与 iteglow 补丁已同步至 desktop-maintenance 永久源目录。版本更新前维护备份，升级 iteglow 需重新检查补丁并执行测试；BIOS变化仍拒绝直接套用旧协议。原始 OEM 二进制、原始 ACPI 表、授权令牌不进入维护资料。
